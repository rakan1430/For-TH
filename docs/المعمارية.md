# المعمارية

## الصورة الكاملة

```
        المتصفّح                   Supabase
  ┌────────────────────┐    ┌──────────────────────────┐
  │ React + TypeScript │    │  Auth                    │
  │                    │───▶│  PostgREST ──▶ public.*  │
  │ lib/api.ts         │    │              (RLS)       │
  │  · لا شرط صلاحية    │    │  RPC ──────▶ دوالّ       │
  │                    │    │              SECURITY    │
  │ lib/format.ts      │    │              DEFINER     │
  │  · كل تاريخ يمرّ به  │    │                 │        │
  │                    │    │                 ▼        │
  │ styles/tokens.css  │    │            private.*     │
  │  · القيم مقيسة      │    │       (خارج سطح الشبكة)  │
  └────────────────────┘    │  Storage (دلاء خاصّة)     │
                            └──────────────────────────┘
```

`public` هو المخطّط الوحيد الذي تكشفه واجهة PostgREST. و`private` **ليس
محمياً بسياسةٍ قد تُنسى — بل لا مسار شبكة إليه أصلاً**. وهذا الفرق جوهريّ:
السياسة تُنسى، وغياب المسار لا يُنسى.

## نموذج البيانات — الأفكار الحاكمة

### المسار على كل صفّ، ومفاتيح مركّبة بينها

كل جدول محتوىً يحمل `track`. والارتباط بين صفّين يمرّ بمفتاح أجنبيّ يحمل
`track` معه:

```sql
foreign key (bank_id, track) references public.banks(id, track)
```

فبنكٌ في القدرات لا يمكن أن يُسنَد إلى قسمٍ في التحصيلي — **لا لأنّ الشفرة
تتذكّر أن تمنع، بل لأنّ القيد يرفض**. و`MATCH SIMPLE` (الافتراضي) لا يفحص
القيد حين يكون `bank_id` فارغاً، وهو السلوك المطلوب بالضبط: الملفّ المفرد
بلا بنكٍ مسموح.

### السريان يُحسب، لا يُحفظ

لا عمود `status` على الاشتراك. عمودٌ محفوظ يحتاج مهمّةً مجدولة تحدّثه، وإن
تأخّرت ساعةً بقي اشتراكٌ منتهٍ «سارياً». `current_date between starts_on and
ends_on` لا يتأخّر أبداً.

### الترتيب من صنع المعلّم

`position` عمودٌ يكتبه المعلّم. وتسلسل البنك يخلط ملفّاتٍ واختبارات في خيطٍ
واحد: «شرح ١، تمارين ١، شرح ٢، تمارين ٢، اختبار البنك» — تدمجهما
`bankItems()` في الواجهة، وتكتب `reorder_bank_items` مواضعهما معاً في
معاملةٍ واحدة.

### المحاولات المتعدّدة أوّلاً لا لاحقاً

```sql
constraint quiz_attempts_per_attempt_uniq unique (quiz_id, student_id, attempt_no)
```

ثلاثة أعمدة لا اثنان. والمشروع السابق بُني على اثنين ثمّ رُقّع.

## الرؤية: ثلاثة شروط مجتمعة

يرى الطالب صفّ محتوىً إذا — وفقط إذا:

1. **منشور** (`is_published`)، و
2. **اشتراكه ساري في مساره** (`has_active_subscription(track)`)، و
3. **أُرسل إليه** (`is_assigned(...)`): للمسار كلّه، أو لمجموعةٍ هو فيها، أو
   باسمه.

والثلاثة في سياسة الصفّ نفسها. والنشر والتوزيع **شرطان مستقلّان**: بنكٌ
موزَّعٌ غير منشورٍ لا يصل.

> وسياسات الأسئلة والخيارات لا تُعيد كتابة هذه الشروط: تستعلم عن
> `public.quizzes` فتخضع لسياستها. فإن ضاق الحقّ يوماً في موضعٍ واحد، ضاق
> معه في الكلّ — ولا يفترق شرطان بمرور الوقت.

## دوالّ الخادم — ثلاث قواعد

1. **لا رفع استثناءٍ بعد كتابة.** `raise exception` يُلغي المعاملة كلّها بما
   فيها كتاباتٌ نجحت قبله. الترتيب دائماً: تحقّق ← اكتب ← **أعد قيمةً**.
2. **لا نجاح كاذب.** `assign_items` تُعيد `(created, skipped, targeted)` لا
   قيمةً منطقية، وتعرضها الواجهة كما هي.
3. **الصلاحية تُفحص لحظة الكتابة.** والدالّة `SECURITY DEFINER` تتجاوز
   السياسات، فتُعيد فحص كل ما كانت السياسة ستفحصه بنفسها.

## الواجهة

- **التوجيه** بالشذرة (`#/…`): الجزء بعد `#` لا يصل أي خادم. و`navigate`
  تُطلق حدثاً خاصّاً لأنّ الانتقال لنفس الشذرة لا يُطلق `hashchange` إطلاقاً.
- **السمة** على `documentElement`، والافتراضي **داكن**، ونصٌّ في `index.html`
  يضبطها قبل أوّل رسم فلا يومض الفاتح.
- **الشبكة** أرضيةٌ حقيقية بمقاس الوحدة نفسها (٢٤ بكسل)، وتُرفع عن الأسطح
  التي يُقرأ عليها نصّ.
- **الأحمر** للفعل الأساسي والتصحيح فقط، وزرٌّ أساسيّ واحد في الشاشة.
- **الأيقونات** SVG خطّي على شبكة 20px. لا إيموجي — ويفحص ذلك البناء.
