# عدّاد "المتصلون الآن" — حضور لحظي حقيقي

> ملحقٌ بحزمة البدء. مصدره منصّة **خُطى المنفصلة تماماً** (اقرأ
> `٠-اقرأني-أولاً.md`) — هذا وصفٌ لآلية عمل، لا شفرة تُنسخ. طبِّقه على
> قاعدة بيانات هذا المشروع الخاصّة به، بأسماء جديدة لا تُطابق خُطى.

---

## ١) الفكرة بجملة واحدة

عدّاد يعرض **عدد الأشخاص المفتوح عندهم الموقع فعلياً هذه اللحظة** —
ليس "عدد المسجَّلين" ولا "عدد الزيارات اليوم"، بل حضورٌ حيّ يتغيّر
فوراً حين يفتح أحدهم الموقع أو يغلقه.

---

## ٢) لماذا ليس عن طريق تحديث كل بضع ثوانٍ (Polling)

الطريقة الساذجة: كل متصفّح يسأل الخادم كل ٢٠-٣٠ ثانية "كم عدد المتصلين
الآن؟" ويحدّث الرقم. **وهذا ما رُفض عمداً في خُطى**، لأنّ فيه ثلاث
مشاكل حقيقية:

1. **بطء الاستجابة** — قد يمرّ ٣٠ ثانية كاملة قبل أن يظهر انضمام شخص جديد.
2. **حِمل غير ضروري على الخادم** — كل متصفّح مفتوح يرسل طلباً متكرراً
   إلى الأبد، بغضّ النظر عن حدوث تغيير فعلي أم لا.
3. **استهلاك بيانات/بطارية زائد** على جهاز الطالب بلا داعٍ.

**البديل المُعتمَد: ميزة "الحضور" (Presence) المدمجة في Supabase
Realtime** — تواصل حيّ عبر WebSocket لا عبر طلبات متكررة، فيتحدّث
العدّاد **فوراً** عند دخول أو خروج أي شخص، بلا أي طلب دوريّ إطلاقاً.

> ⚠️ تحتاج أن يكون **Realtime مفعَّلاً** على مشروع Supabase — وهو مفعَّل
> افتراضياً في كل مشروع جديد، فلا إعداد إضافي عادةً.

---

## ٣) الآلية خطوة بخطوة

### أ) إنشاء قناة حضور واحدة، بمفتاح هوية المستخدم

```js
const presenceChannel = sb.channel("اسم-غرفة-فريد", {
    config: { presence: { key: uid } }
});
```

- **اسم الغرفة** ثابت يُشارَك بين كل من يفتح الموقع — كأنّهم جميعاً
  دخلوا نفس الغرفة الافتراضية.
- **المفتاح (`key`)** هو معرّف المستخدم نفسه. هذا مهمّ: لو فتح نفس
  الطالب الموقع من جهازين، لا يُحسَب مرّتين — المفتاح واحد لكل شخص لا
  لكل جلسة.

### ب) الاستماع لحدث "sync" — وهو قلب الآلية

```js
presenceChannel
    .on("presence", { event: "sync" }, () => {
        const state = presenceChannel.presenceState();
        const count = Object.keys(state).length || 1;
        // اكتب count في كل مكان يعرضه في الصفحة
    })
    .subscribe(async (status) => {
        if(status === "SUBSCRIBED"){
            await presenceChannel.track({ online_at: new Date().toISOString() });
        }
    });
```

**كيف يعمل هذا فعلياً:**

1. حين يفتح أي شخص الموقع، يشترك في القناة (`.subscribe`).
2. بمجرّد نجاح الاشتراك، **يسجّل حضوره** (`.track`) — أي "أنا هنا الآن".
3. Supabase يبثّ تلقائياً حدث `sync` **لكل من في القناة** — أي أنّ كل
   متصفّح مفتوح عند أي شخص آخر يعرف فوراً أنّ شخصاً جديداً انضمّ.
4. `presenceState()` تعيد كائناً مفاتيحه هي معرّفات كل الحاضرين حالياً؛
   **عدد المفاتيح = عدد المتصلين**.
5. حين يغلق أحدهم الصفحة، ينقطع اتصاله فيُبثّ `sync` جديد للجميع بعددٍ
   أقلّ — تلقائياً، بلا أي كود إضافي.

### ج) الفشل الصامت مع بديل ثابت

```js
try{
    // … إنشاء القناة والاشتراك
}catch(e){
    console.error("تعذّر تفعيل الحضور اللحظي:", e);
    // اعرض "1" بدل رقم متحرّك — العدّاد ميزة جانبية، لا الميزة الرئيسية للموقع
}
```

⚠️ **قاعدة تصميم مهمّة:** لو تعطّلت خدمة الحضور اللحظي لأي سبب (شبكة،
إعداد ناقص)، **لا يجوز أن يتعطّل الموقع كلّه معها**. العدّاد ميزة جانبية
تجميلية، فيُعرض رقمٌ ثابتٌ آمن (١) بدل رقمٍ متحرّك عند الفشل، ويُسجَّل
الخطأ في وحدة التحكّم للمطوّر فقط — الطالب لا يرى رسالة خطأ على عدّادٍ
جانبي.

---

## ٤) تفعيل الميزة مرّة واحدة لكل جلسة — لا في كل مرّة يُفتح فيها القسم

```js
let initialized = false;
async function initSectionIfNeeded(){
    if(initialized) return;
    initialized = true;
    // … بقيّة تهيئة القسم
    startPresenceHeartbeat();
}
```

⚠️ **لماذا الحارس ضروري؟** لو استُدعيت دالّة بدء الحضور كل مرّة يفتح
فيها المستخدم قسم المجتمع (بدل مرّة واحدة فقط)، تُنشأ **قناة جديدة فوق
القناة القديمة** في كل مرّة — تسريب اتصالات، وربما عدّاد يحسب نفس الشخص
أكثر من مرّة. راية بسيطة (`initialized`) تمنع ذلك تماماً.

---

## ٥) أين يظهر العدّاد — يمكن أن يظهر في أكثر من مكان بنفس القيمة

في خُطى يظهر الرقم نفسه في ثلاثة مواضع مختلفة من الصفحة في آنٍ واحد
(بطاقة كبيرة في قسم، رقم صغير في لوحة التحكّم، رقم آخر في مكان ثالث) —
لأنّ حدث `sync` الواحد يحدّث **كل عناصر DOM** المرتبطة به دفعة واحدة عند
كل تغيير. لا حاجة لثلاث قنوات ولا ثلاثة استعلامات — قناة واحدة، وكل
مكان يعرض الرقم يُحدَّث من نفس معالج الحدث.

---

## ٦) ملخّص الفروقات المهمّة عن عدّاد "عدد الزيارات" العادي

| | عدّاد الحضور اللحظي | عدّاد الزيارات التراكمي |
|---|---|---|
| المصدر | اتصال WebSocket حيّ | صفّ في قاعدة بيانات يُزاد بكل زيارة |
| يتحدّث | فوراً عند الدخول/الخروج | لا يتحدّث تلقائياً |
| يمثّل | من **الآن** في الموقع فعلياً | كم زيارة **حدثت على الإطلاق** |
| يهبط الرقم؟ | نعم — عند خروج أي شخص | لا — لا يهبط أبداً |

**عدّاد المعلّم المطلوب هنا هو النوع الأوّل** — "كم طالباً في موقعي
الآن هذه اللحظة"، لا "كم زيارة وصلتني منذ البداية".

---

## ٧) قائمة تحقّق سريعة عند التطبيق

- [ ] التأكّد أنّ Realtime مفعَّل على مشروع Supabase الخاصّ بهذا المشروع
- [ ] اسم قناة واحد ثابت يُستعمل في كل الصفحة
- [ ] `key` في إعداد الحضور = معرّف المستخدم، لا معرّف الجلسة
- [ ] حارس تهيئة (`initialized`) يمنع إنشاء القناة أكثر من مرّة
- [ ] بديل ثابت آمن عند فشل الاتصال — لا رقم متحرّك مكسور ولا رسالة خطأ ظاهرة للمستخدم
- [ ] اختبار فعلي: افتح الموقع في نافذتين مختلفتين وتأكّد أنّ الرقم ٢،
      ثمّ أغلق واحدة وتأكّد أنّه يعود ١ **بلا تحديث يدوي للصفحة**
